# Command: /audit:report

Write or regenerate AUDIT_REPORT.md from cached findings. Does not re-run analysis — reads from the findings cache.

## Usage

```
/audit:report
```

---

## Execution

### Step 1 — Read Cache and State

Read both files:

```bash
cat .claude/vibeaudit/findings-cache.json
cat .claude/vibeaudit/state.json
```

`findings-cache.json` contains all findings from the last audit, keyed by file path.
`state.json` contains audit metadata: date, stack detected, file counts, previous state hash.

If either file is missing, print:

```
No audit data found. Run /audit or /audit:full first to generate findings.
```

Then stop.

### Step 2 — Derive Project Name

Read `package.json` for the `name` field. If not found, use the directory name of the current working directory.

### Step 3 — Write AUDIT_REPORT.md

Write the file to the project root using this exact structure:

---

```markdown
# Audit Report — [project name] — [date from state.json]

## Summary
| Severity | Count |
|---|---|
| 🔴 Critical | N |
| 🟠 High | N |
| 🟡 Medium | N |
| 🟢 Low | N |
| ℹ️ Info | N |
| **Total** | **N** |

## Stack
[Comma-separated list of detected stacks from state.json]
Detected from: package.json

## Audit Metadata
- **Date**: [date]
- **Files audited**: [N new + M cached from state.json]
- **Cache status**: [fresh / stale — based on age of state.json]

---

## 🔴 Critical Findings

### [Finding title — derived from description]
**File**: path/to/file.ts:LINE
**Category**: Security
**Description**: Full description of the issue and why it is exploitable.
**Fix**:
```[language]
// concrete remediation code
```

[repeat for each Critical finding]

---

## 🟠 High Findings

### [Finding title]
**File**: path/to/file.ts:LINE
**Category**: [Security | Performance | Quality]
**Description**: ...
**Fix**: ...

[repeat]

---

## 🟡 Medium Findings

[same format]

---

## 🟢 Low Findings

[same format]

---

## ℹ️ Info

[same format]

---

## Fixed Since Last Audit

[Only include this section if state.json contains a previous_state_hash and the previous cache exists]

The following issues from the previous audit are no longer present:
- ~~path/to/file.ts:LINE — Description~~ (resolved)

---

*Generated by vibeAudit on [date]*
```

---

### Grouping Rules

Within each severity section:
1. Group findings by category: Security first, then Performance, then Quality.
2. Within each category, sort by file path alphabetically.
3. Use a level-3 heading (`###`) for each finding with a human-readable title derived from the description.

### Finding Title Derivation

Generate a short (5-10 word) title from the finding description. Examples:
- "Missing Stripe webhook signature verification" (not "🔴 CRITICAL | Security | src/app/api/webhooks/stripe/route.ts:23")
- "N+1 query in user activity feed"
- "Swallowed error in payment mutation"

### Empty Sections

If a severity level has zero findings, omit that section entirely from the report. Do not write `## 🟢 Low Findings` with nothing under it.

---

## Confirmation

After writing the file, print:

```
AUDIT_REPORT.md written.
[N] findings across [severity levels present].
```
